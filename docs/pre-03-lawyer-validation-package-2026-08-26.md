# L-A. Executive Summary

## 一句話

一個由平台以**自己名義**銷售、由**第三方創作者授權**內容、
以**人工銀行匯款＋人工核帳**收款、並**定期人工撥付創作者報酬**的數位教材平台，
在正式上線前，需要確認其**支付定性**、**授權鏈設計**與**消費者條款結構**是否成立。

## 最優先的一題

> **`Q-02`：現行「買家匯款至平台帳戶 → 平台人工核帳 → 平台撥款給創作者」的實際流程，

理由：若答案為「是」，則**整個 Phase 1 商業模式必須重新設計**，
所有條款、產品流程與工程排程都將改變。其他問題的答案都建立在此之上。

# L-B. Facts（事實陳述）

## B-1. 商業模式（Phase 1）

```text
創作者（Creator）
   │  授權教材，並授權平台得再授權予買家
   ▼
平台（Platform）
   │  以平台自己名義，向買家銷售「數位教材使用授權」
   ▼
買家（Buyer）
```

- 買家的**契約相對人是平台**。平台與買家之間為一般消費者交易。
- 創作者與平台之間為**另一份**內容授權暨合作報酬契約。
- Phase 1 **不建立**買家與創作者之間的直接買賣或付款關係。
- 創作者多為**個人**（教師、教材創作者）；買家多為**個人消費者**（家長、教師）。

## B-2. 實際金流（Phase 1，全人工）

```text
1. 買家於平台建立訂單
2. 平台顯示平台自己的收款銀行帳戶與付款期限
3. 買家自行至銀行／ATM／網銀轉帳至平台帳戶
4. 買家於平台上傳匯款憑證（截圖或收據影像）
5. 平台管理員登入平台銀行帳戶，人工比對是否收到該筆款項
6. 比對相符 → 平台核准 → 買家取得該教材之下載權
7. 平台依創作者契約，於固定週期計算該期應付創作者之報酬
8. 平台另行以人工銀行匯款方式撥付創作者
```

**目前不存在：** 信用卡、電子支付、金流 API、Webhook、自動對帳、自動分帳、自動撥款。

## B-5. 授權鏈

- 創作者對平台之授權，目前規劃為**非專屬授權**（創作者得於其他通路自行銷售）。
- 平台需向買家授予使用授權 → 此為**再授權**。
- 買家取得之授權為**單一使用者／單一教學者授權**：
  得供本人、其子女、或其所負責之學生使用；**不得**分享予其他教師或轉售。
- 教材可能因創作者提交新版本而更新；平台需為既有買家保存並繼續交付其履約時之版本。

## 第一優先

### `Q-02` 支付定性 —— 是否構成第三方支付／代理收付？

**背景：** 見 `B-2` 之完整金流。全部為人工作業，無任何金流 API。
款項先進入平台自己的銀行帳戶，平台核帳後開通教材，之後另行按期撥付創作者。

**目前假設：** 產品端認為，在「平台為出賣人」之架構下，
買家係向平台支付其向平台購買之價金，並未指示平台將該筆款項轉付予創作者；
創作者亦非該筆交易之收款方，而係另一份契約之債權人。
因此**不構成**「接受付款方基於實質交易所移轉之款項，並…將該實質交易之款項移轉予收款方」之業務。

**請確認：**

1. 上述假設是否成立？若不成立，**關鍵理由為何**？
2. 在此類「平台自營＋第三方內容授權＋抽成式報酬」的架構中，
   **哪些實質事實對認定的影響最大**？（例如：定價權歸屬、盈虧承擔、
   退款風險由誰承擔、報酬是否隨個別交易連動、資金是否分離保管等）
3. `B-3` 所列 9 項 Product Invariants，是否**足以**支持出賣人定性？
   有無**多餘**（可放寬）或**不足**（須補強）之項目？
4. 是否有其他需要登錄或許可之支付服務類型（非第三方支付）可能被觸及？
5. 若最終仍可能被認定涉及代理收付，**最小的合規路徑**為何？

## 授權鏈（Licensing）
