# T-A. Executive Summary

一個由平台以**自己名義**銷售數位教材、內容來自**第三方個人創作者授權**、

# T-B. Facts（事實陳述）

## B-1. 商業模式（Phase 1）

```text
創作者（個人為主）
   │  授權教材，並授權平台得再授權予買家
   ▼
平台
   │  以平台自己名義，向買家銷售「數位教材使用授權」
   ▼
買家（個人消費者為主：家長、教師）
```

- 買家之契約相對人為**平台**。
- 創作者與平台之間為**另一份**內容授權暨合作報酬契約。
- 平台依約定比例，就「本期符合條件之**淨銷售**」計算應付創作者之報酬。
- **本平台為純數位商品**：買家於線上取得下載權，無實體寄送。
- 買家**絕大多數為非營業人**（個人），少數可能為機構。
- 創作者**以個人為主**，未來可能有商號或公司。

> **法律定性尚未確定：** 平台是否確為出賣人、或可能被認定為受託代銷，
> 已另行委請律師確認（`Q-01`／`Q-02`）。**該答案會影響本文件多題**，
> 請於回覆時標明「若定性為 X 則…」。

## B-2. 實際金流（全人工）

```text
1. 買家於平台建立訂單
2. 平台顯示平台自己的收款銀行帳戶
3. 買家自行銀行轉帳至平台帳戶
4. 買家上傳匯款憑證影像
5. 管理員登入平台銀行帳戶人工比對
6. 比對相符 → 核准 → 買家取得下載權
7. 平台按固定週期計算該期創作者報酬
8. 平台另行人工銀行匯款撥付創作者
```

**目前不存在：** 信用卡、電子支付、金流 API、自動對帳、自動分帳、自動撥款。

## B-3. 目前系統之時間欄位（**重要，請特別注意**）

| 欄位 | 目前實際語意 |
| --- | --- |
| `orders.created_at` | 訂單建立時間 |
| `orders.paid_at` | **管理員核准時間** —— 名稱雖為「付款時間」，實際記錄的是核准事件 |

產品端已規劃新增三個彼此獨立的時間欄位：

```text

payment_approved_at         管理員核准之時間
```

**請確認稅務上應以何者為準**（見 `Q-07`）。
