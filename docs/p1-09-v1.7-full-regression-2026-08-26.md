## 3. 通過但內容被弱化

### `MR-11` —— `K5` 把已查證的具體要求軟化成「按適用法規保存」

**v1.5 記錄的、且我已對原文查證的內容：**

> **§16**：業者於業務終止後，其所蒐集、處理或利用之個人資料應依下列方式處理，
> 並**留存記錄至少五年**：
> 一、**銷毀**：銷毀之方法、時間、地點及證明銷毀之方式。
> 二、**移轉**：移轉之原因、對象、方法、時間、地點及受移轉對象得蒐集該個人資料之合法依據。
> 三、**刪除、停止處理或利用**：其方法、時間或地點。

**v1.7 `K5` 現況：**

> 如進行資料移轉，需確認接手方具有合法蒐集依據並留下紀錄；
> 依法需保存的終止處理紀錄應**按適用法規保存**。

「受移轉對象之合法依據」保住了 ✅，但：

- **「至少五年」消失**
- **三類處理各自的應記載欄位消失**

「按適用法規保存」把一個**已經查證過、可直接寫進規格的具體數字**，
退回成「去查法規」。這正是前五輪反覆出現的失敗模式，只是這次發生在細節層。

**修法：** `K5` 恢復「留存記錄**至少五年**」與三類處理的應記載欄位。

### `MR-15` —— 措辭指向一個已被刻意退役的產物

`MR-15` 寫「**Coverage Matrix** / Master Regression Matrix itself exists」。

v1.7 有 Master Regression Matrix ✅，但**沒有 Coverage Matrix** ——
而那是 v1.6 依「不得再維護另一份看似完整的清單」**刻意合併掉的，做法正確**。

問題只在 `MR-15` 的字面仍要求一個不該再存在的東西。
下一輪檢查者會據此開一張假的 FAILED。

**修法：** `MR-15` 改為「**Master Regression Matrix itself exists and is the single source**」。

## 4. 法源依據流失（規則在、理由不在）

這兩項不影響 MR 判定，但會讓規則在未來被當成「產品偏好」而放寬：

| 項目 | 規則 | 流失的依據 |
| --- | --- | --- |
| `MR-09` CONTENT-LIMIT | 平台不得自行實質修改教材內容 | **消保法 §8 II**：「改裝、分裝商品或**變更服務內容**者，**視為第七條之企業經營者**」—— 一旦平台實質改教材，就從經銷者升格為製造者，喪失「已盡相當注意」的免責空間。第四輪 `REG-1` 的修法建議是「`E3` 補上 §8 II 作為理由」，**未執行** |
| `C2` 逐項授權 | 授權必須逐項明確，不能概括 | **著作權法 §37 I**：「其**約定不明之部分，推定為未授權**」 |

**修法：** 兩處各補一句法源。規則已經對了，只是失去了不可辯駁的理由。

## 5. 新發現：`18+` 被軟化成「原則上 18+」

`A1`（第 265 行）與 `I`（第 490 行）都寫「正式會員、Buyer、Creator **原則上** 18+」。

前六輪一致的表述是 **18+**（一個可在註冊流程強制執行的產品規則）。
「原則上」讓它變成有例外的政策，但**沒有定義例外是什麼、由誰核准**。

這對一個**會在 code 裡被實作成硬性檢查**的規則是有害的模糊：
工程看到「原則上」會問「那例外怎麼做」，而目前沒有答案。

**修法：** 恢復為 **18+**（無例外）。若真的要留例外，必須寫明例外條件與核准流程，
否則就是給實作留一個沒有規格的分支。
